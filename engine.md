Goal

Run a full real test cycle for Koya using:

Daraja sandbox for payment simulation
Bria for wallet/UTXO/batch/PSBT lifecycle
DFNS sandbox for signing only
QuickNode testnet4 for Bitcoin network interactions

Do not use mocks unless a dependency is unavailable and you explicitly document the blocker.
Before running any tests, manually validate that all services and configuration are correct.

At the end, produce a test evidence pack with logs, IDs, txids, funding address, screenshots/URLs where applicable, reconciliation result, and pass/fail outcomes.

Important architectural rule

DFNS signs; Bria owns the receive address, UTXO tracking, PSBT building, and broadcast lifecycle.

Therefore:

the funding address must be generated by Bria
that Bria wallet must be linked to the DFNS-backed xpub/signing path
do not fund an arbitrary DFNS wallet address unless it is the exact address derivation path Bria is tracking

Test cases

Phase 4 — Bria + DFNS signing tests

Once the wallet is funded and Daraja payment path is confirmed, run the payout/signing flow.

Test cases
T4. Happy path payout signing
Create/trigger a conversion that results in BTC delivery.
Verify DfnsBtcDeliveryProvider.send() submits payout to Bria.
Wait for payout_committed.
Verify Bria produces an unsigned PSBT batch.
Verify PsbtSigningService stores payout_psbts metadata.
Verify DFNS receives sign request over mTLS.
Verify DFNS returns signed PSBT.
Verify Koya stores dfns_request_id and signed PSBT metadata.
Verify Koya submits signed PSBT back to Bria.
Verify Bria broadcasts and later settles.
Verify conversion becomes COMPLETED.

Capture:

externalId
payout ID
batch ID
psbt record
dfnsRequestId
txid
settlement event
final conversion/session state
T5. Duplicate sign request idempotency
resend the same DFNS sign request with same externalId / idempotency key
verify existing result is reused
verify no duplicate PSBT record mutations
verify no duplicate broadcast
T6. Duplicate DFNS webhook idempotency
replay the same DFNS webhook
verify processed_webhooks dedup works
verify no duplicate state transitions or ledger writes
T7. Manual payout resend
trigger a resend/retry path for a payout that has not yet settled
verify the system handles it safely
verify idempotency and no double-spend behavior
T8. Failure recovery

Simulate at least two failure scenarios:

DFNS temporary signing failure
Bria broadcast or settlement delay/failure

Validate:

circuit breaker behavior
sign pending metric behavior
retry behavior
safe final status (DELIVERY_PENDING, FAILED, or manual review as appropriate)

Technical guidance for the agent
Funding address decision

Generate the address from Bria, not DFNS directly, because:

Bria must detect and track the UTXO
Bria builds the PSBT
DFNS only signs
Real service preference

Use:

real Daraja sandbox
real DFNS sandbox
real Bria
real QuickNode testnet4

Only use a fallback mock if a provider is unavailable, and clearly document that as a blocker.

Conservative test strategy

Use your faucet balance carefully:

50,000 sats for initial wallet/UTXO validation
then progressively larger scenarios if the first run passes
avoid consuming all testnet funds in one pass
Manual validation before test execution

Do not start any payment or payout test until:

all health checks pass
drivers are confirmed real
address generation succeeds
Bria sees the wallet/xpub correctly
DFNS mTLS health is green
Acceptance criteria

This test phase is successful only if:

a real Bria funding address is created and funded
Bria detects the UTXO
Daraja sandbox payment is confirmed through callback
DFNS signs a real PSBT
Bria broadcasts and settles
conversion completes end-to-end
duplicate callbacks/sign requests are safely idempotent
manual resend and failure recovery are validated
reconciliation and archival jobs are proven
evidence pack is complete and usable by humans
